HOW TO OPEN
--------------------------------------------------------------------------------
If you installed via the installer (LaFirma_Setup): click the
"LaFirma Remux Forge" shortcut on the Desktop or in the Start Menu.

If you are using the portable folder: double-click
"Abrir_LaFirma_JANELA.vbs".

Either way the window opens on its own, with no black console window
behind it, reads the "00_Arquivos_Base" folder, and already builds the
queue with each episode's diagnosis - nothing is converted until you click
Start.

If the shortcut ever fails to open, there are TWO plan Bs, and they do
different things:

  "Abrir_LaFirma_JANELA.bat"     - opens the SAME window, but with the black
                                   console behind it. That console is where
                                   you see the error the normal mode swallows.
  "Converter_AUTO_DIRETO.bat"    - skips the window and runs the engine
                                   straight in the console. Use it when the
                                   window itself won't open.


WHAT THIS PROGRAM DOES
--------------------------------------------------------------------------------
For every .mkv file inside the "00_Arquivos_Base" folder, it runs a
DIAGNOSIS and then 5 WORK STEPS, each with its own progress bar:

  ·  DIAGNOSIS - reads the frame rate, the duration and the tracks, and
     decides what will be done. It changes nothing and takes 2 to 4 seconds.
     That is why it has no number: it is not the work, it is the decision
     about the work.

  1. Extracts the raw video from the MKV (no re-encoding - zero quality loss)
  2. Converts the Dolby Vision to Profile 8.1.
     - If the video is ALREADY Profile 8.x (no Enhancement Layer), this step
       is SKIPPED automatically and the video is reused ("[NOT NEEDED]
       Already Profile 8.1"). Profile 7 is converted normally; Profile 5
       has its own path (see below).
     - The diagnosis now tells you WHICH KIND of enhancement layer a Profile
       7 file has, because that changes what the conversion means. It reads
       this from the file itself, over a few short stretches of video:

         MEL   ->  [WILL BE CONVERTED], in green. The enhancement layer
                   carries no picture; discarding it does not change the
                   video.

         SIMPLE FEL -> [WILL BE CONVERTED WITH A CAVEAT], in orange. The
                   layer does carry picture, but it is refinement: the fine
                   residual between the 10-bit base and the higher precision
                   of the master. Dropping it costs gradient and shadow
                   detail that only shows on a paused frame, looked at
                   closely. While watching, you do not see it.

         COMPLEX FEL -> [CONVERSION NOT RECOMMENDED], in red. Here the extra
                   layer is not refining, it is RAISING the brightness - and
                   the L1 left in the file describes that higher peak. The
                   TV is then told to tone map to a brightness that is no
                   longer there.

                   THE PROBLEM WAS NEVER THE PIXEL, IT WAS THE INSTRUCTION.
                   L1 is the nits message handed to the TV; what ruins the
                   picture is that message being wrong, not the layer being
                   gone.

                   Red does NOT block anything: if you start it, it
                   converts. And it is worth knowing that most digital
                   players (Shield, Apple TV, Zidoo, TVs) discard that layer
                   anyway - on those, the file already plays today the way
                   the converted one will. The UNDERSTAND button, on the top bar,
                   explains this at length - and its final section gives
                   the addresses where you can check every claim for
                   yourself. It opens in whichever language the flag next
                   to the button is set to.

                   What separates Simple from Complex is a number: the
                   file's L1 against the mastering display peak. If the file
                   does not declare that peak, the program says it does not
                   know, instead of picking a side.

         [NOT MEASURED] -> the layer could not be read on this file. That
                   does not mean it is clean; it means it was not measured.

     - Profile 5 is a different case, and it has its own path. Getting to
       Profile 8.1 from it would require RE-ENCODING the video - it is not
       a remux, and there is loss. What P5 needs is not a profile
       conversion: it is a container devices will read. So the program
       remuxes it to MP4, with the video COPIED and the dvh1 tag - that is
       how a P5 plays on Apple TV, on Infuse and on the players that ignore
       .mkv. On that path: audio is copied when it fits in MP4 (E-AC-3,
       AC-3, AAC) and becomes E-AC-3 640k when it does not (TrueHD, DTS);
       text subtitles become mov_text; PGS subtitles are discarded, because
       image subtitles have no representation in MP4 - and there is no OCR
       on this path. The program announces each of these before doing it.
  3. Converts the MAIN audio track to E-AC-3, following this rule:
     - Dolby TrueHD/MLP  -> E-AC-3 Atmos (via DeeZy), if DeeZy is available.
     - DTS / DTS-HD / DTS:X -> standard E-AC-3 (via ffmpeg).
     - If the main track is ALREADY E-AC-3, AC-3 or AAC (formats modern TVs
       already play natively), the conversion is SKIPPED ("[NOT NEEDED]
       Already ... (Compatible)").
     The decision looks at the movie's MAIN audio track (TrueHD/Atmos in any
     language -> English track -> the track flagged default by the remux ->
     first track; always ignoring director's commentary), and IGNORES tracks
     in a different language than the main one when deciding whether a
     ready-made track already exists to reuse - a PT-BR dub never cancels
     the conversion of the original English audio.
  4. If a Brazilian Portuguese subtitle exists, it is prepared as the
     player's DEFAULT: ready text (.srt/.ass) is used directly; PGS
     (image-based) is converted via OCR. If neither exists, the step is
     skipped.
     OCR is done by PgsToSrt / Tesseract (needs .NET 8 - the installer
     installs it, or offers the Microsoft download when it is not bundled). Corretor_Legenda then runs and repairs blocks that
     came out as garbage. There is nothing to choose or configure.
     (Up to 1.9 seconv / BinaryOCR shipped too; it was removed in 2.0
     because it was rejected in every movie measured from 13/08 to 22/09 -
     its Latin.db did not match the subtitle fonts and 8% to 73% of the
     characters came out as '*' - and the final subtitle always came from
     PgsToSrt.)

     This is the only step that runs SEVERAL programs in a row, and each one
     is named on screen while it works:

         OCR (PgsToSrt / Tesseract)
         Garbage-block review (Corretor_Legenda)
         Short-line re-OCR (Reocr_Legenda / Tesseract PSM 6)

     The RE-OCR is the last one and fixes OCR's worst case: a one or two word
     line. It is what turns "INF TOL" into "Não!". It only touches blocks
     that look suspicious, and only replaces one when the new reading passes
     its own check - a good line is never touched. Tesseract ships inside the
     package (tools\Tesseract\), so this works on a freshly formatted
     machine with nothing installed.

  5. Remuxes the final MKV keeping only what matters: main audio + the
     new/reused track (director's commentary, extra dubs and other tracks
     are discarded); new PT-BR subtitle (.SRT, the default) + the original
     PT-BR PGS (kept next to it, for whoever prefers it) + one English
     subtitle (the full one; SDH only when there is no other). Other
     languages and forced tracks are discarded. Video and chapters
     are always kept intact. SAFE MODE: if the audio conversion fails or
     there is no PT-BR subtitle to generate, nothing is discarded on that
     front.

  ·  VERIFICATION - the program actually DECODES 10 short excerpts spread
     from the start to the end of the file it has just built. This is not a
     header read: the video is really opened. If any excerpt fails, the same
     test runs at the SAME points on the SOURCE file, and the program tells
     you which of the two is at fault - instead of you finding out while
     watching. Nothing is deleted or rejected: what to do with the file is
     your call. It has no number (it stays off the ruler) and takes a few
     seconds, because seeking uses the file index.

  ·  CLEANUP - deletes that episode's temporary files. Also has no number:
     it is instantaneous on every file measured so far.

A STEP WITH NOTHING TO DO IS SKIPPED, and you can see it: its slice
disappears from the progress ruler instead of sitting there as a gap. Real
example: a file already in Profile 8.1 whose audio you chose to keep runs
only 3 of the 5 steps, and the ruler shows 3 slices.

Incompatible files (non-HEVC, or with no Dolby Vision at all) are skipped
with a clear message, without wasting time on a file that isn't a
candidate.

The final result is placed in "01_Arquivos_Finalizados", with the original
file name plus the [BL+RPU] tag (e.g. "Movie [BL+RPU].mkv"), so the converted
file is never mistaken for the source. Profile 5 comes out as .mp4 with the
original name. Nothing inside "00_Arquivos_Base" is ever deleted or modified.

The window language is the one chosen in the installer, or with the flag
button on the top bar (saved in IDIOMA.txt). The labels below are the
English ones; with the window in Portuguese they appear in Portuguese.


THE WINDOW - QUEUE AND TRACKS
--------------------------------------------------------------------------------
The "Queue" tab lists every episode found, one per row, with SIZE,
what will happen to DOLBY VISION / AUDIO / PT-BR SUBTITLE (shown as
"A → B" when it will convert), and the STATUS of each. Episodes that have
real work to do are auto-checked; episodes already done (nothing to
convert) come unchecked, but can be checked manually to reprocess.

Click an episode and open the "Video Tracks" tab to see the
track-by-track diagnosis (video, audio, subtitles, chapters) exactly as
the engine will decide it - it's the same decision that goes into the
conversion, not a separate prediction.

Toolbar buttons: "[F1] Start", "[F2] Pause", "[ESC] Cancel", "[F3] Open
Source" and "[F4] Open Output" (open the folders in Explorer), "[F5] Refresh" (re-scan the
folder; blocked during a conversion), "[F11] Full Census" and "[F12] Measure
MEL x FEL" (see their own section below), "Log" (shows this session's log
live - this is what to send me when something looks off) and "Tools" (checks
each tool one by one and shows WHERE each one is).

Right below the toolbar sit the two paths - INPUT folder and OUTPUT folder.
CLICK ON THE PATH ITSELF to change the folder: it opens the Windows folder
picker, with a tree, path typing and search. No button needed.

On the right-hand side, during a conversion, sit the five that decide whether
a piece of the work happens at all:

    dovi_tool   DeeZy   PgsToSrt   Tesseract   mkvmerge

    green  = found
    amber  = OPTIONAL and missing - that part is skipped, the rest runs
    red    = REQUIRED and missing - the conversion will not run

The STATUS column in the queue also follows along live: the row being
converted shows "Converting · Step n/5", finished ones show "Converted".


MEASURE MEL x FEL [F12] AND FULL CENSUS [F11]
--------------------------------------------------------------------------------
[F12] MEASURE MEL x FEL (on by default): while reading the folder, the
program reads a few 2-second pieces of every Profile 7 film and classifies
the extra layer. The row colour in the Queue comes from this, and ONLY from
this:

    green  = MEL          - the extra layer carries no picture
    orange = Simple FEL   - it does, but within the master's brightness
    red    = Complex FEL  - it asks for more brightness than the master declares

Turned off, reading is faster and the file shows "EL not measured" - never
as clean.

[F11] FULL CENSUS: only for Complex FEL. Reads the RPU of the WHOLE film
(far longer than the sample: on Saving Private Ryan, 5 s for the sample
against 1m50 for the census) and counts how many scenes ask for more
brightness than the master. The button shows the percentage; clicking again
(or F11) cancels. The queue stays free during the census, but starting the
conversion ends it (both would read the same disk).

THE CENSUS INFORMS, IT NEVER CHANGES THE COLOUR. It adds numbers (how many
scenes, the peak) to the diagnosis and the log. A Complex FEL with few
scenes stays red: the colour says what the layer IS, the census says how
much it weighs.


MANUAL MODE - FORCE A DIFFERENT CHOICE ON ONE VIDEO
--------------------------------------------------------------------------------
By default the engine decides everything on its own (rule above). To
change the outcome for a specific episode:

1. Tick the video's box in the Queue tab. The mode button, which until then
   said "Tick the video to edit" (greyed out), now shows "Mode: Automatic" -
   click it to switch to Manual.
2. In the Video Tracks tab, every audio and subtitle row gets a
   selector with three options:
     CONVERT   - force conversion even if a ready-made track already
                 exists to reuse.
     KEEP      - keep the track as-is from the source file, no
                 conversion (e.g. keep a dub the automatic rule would
                 have discarded).
     DROP      - remove the track from the final file.
3. If you don't touch any verb, the episode follows the automatic rule
   normally - Manual only kicks in where you chose something different.

The video track itself is never editable (the Dolby Vision profile is the
engine's decision, not the user's).


CONTROLS DURING CONVERSION  ([F1] / [F2] / [ESC])
--------------------------------------------------------------------------------
  [F1]  START - begins converting the checked queue. Only works while
        nothing is running (the button is disabled during conversion).

  [F2]  PAUSE / RESUME (single key, toggles) - pausing actually freezes
        the running process (ffmpeg, dovi_tool, DeeZy, mkvmerge or the
        OCR); while paused it uses no CPU and no disk. The screen shows a
        large PAUSED banner. Resuming continues exactly where it left
        off; paused time doesn't count toward progress.

  [ESC] CANCEL - asks for confirmation before acting (the keyboard
        default is NO, so a reflex Enter won't cancel by accident). If
        confirmed, it stops the current process, deletes the
        half-finished output and that episode's temporary files, and
        stops the batch (remaining episodes are not processed).

Closing the window with the X during a conversion asks the same
confirmation - closing mid-run is cancelling by another name. And if the
conversion finishes on its own right while you're reading the question,
the program notices and won't act on work that's already done.


THE TIME REMAINING
--------------------------------------------------------------------------------
The footer shows three clocks: STEP, VIDEO and QUEUE. The queue line also
shows "Should Finish Around HH:MM · Time Left".

That number is counted from the current step forward: what is left of the
current step (measured by ITS OWN pace, not from a table), plus the steps
still to come, plus the final file check, plus the remaining videos in the
queue. If a step runs late the number goes up - slowly, never in jumps. And
it does not vanish at the end: while the program verifies and cleans up, it
keeps counting down.

In practice, on an idle machine, it is off by about 3% from start to finish.
If you open a game or another heavy program midway, the conversion takes
longer and the estimate falls short - there is no way to predict that.

The program also MEASURES the source disk speed before starting (three short
reads, the best one wins) and adjusts the math: a film on a mechanical HDD
takes longer than the same film on an SSD, and the estimate already knows it.


HOW MUCH DISK SPACE DO I NEED?
--------------------------------------------------------------------------------
It depends on whether the video needs Dolby Vision conversion. There are two
factors, and the program uses the right one per file:

    3.15x the episode size   when DV is converted (7.x -> 8.1). Extracted
                             video + converted RPU + final file coexist on
                             disk for a while.

    1.6x  the episode size   when the video is already Profile 8.1 and never
                             leaves the container. The two loose video files
                             simply do not exist.

The DOLBY VISION column in the queue tells you which case it is: an arrow
(->) means 3.15x.

The screen shows, live, the space needed, the free space now and what would
be left - with a red warning if it isn't enough. That number is the LARGER of
two calculations: the batch one (sum of estimated outputs + 2.15x the biggest
file) and the peak of a single episode. It shows the larger on purpose: until
16.60 the screen used only the loose calculation and said "it fits" three
seconds before the engine refused for lack of space.

With SOURCE and OUTPUT on different drives the math splits: the temporary
files live on the source drive (the factor minus 1x) and the final file goes
straight to the output drive (about 1x). The program checks both and, if one
is short, names the drive. During the conversion "Free Now" shows both.

The real check happens again, per file, when each episode's turn comes: if a
specific episode doesn't have enough space by then, it is skipped with a
warning, without blocking the rest of the batch.

Each episode's temporary files are deleted when that episode finishes -
success, failure or cancellation. The exception is the machine crashing or
the process being killed mid-run: then nobody is left to delete them and the
_ddvt_temp_* folder stays. The program sweeps those orphan folders away by
itself at the start of the next run, logging the path and size of what it
removed.


THE SESSION LOG
--------------------------------------------------------------------------------
Every time the window opens, it creates a new file:

    LaFirma_motor_log_<date>_<time>.txt

saved inside the "_logs" folder, next to LaFirma_JANELA.ps1 (created
automatically the first time). The engine writes its own log there too,
as "log_conversao_<date>_<time>.txt" - both logs from a conversion
session live together in "_logs", without mixing in with the finished
episodes in "01_Arquivos_Finalizados". It records the environment, every
state change, every click/key press and any error - it's the proof of
everything that happened in the session. The "Log" button shows the same
content live inside the program.

If something looks off, this is the file to send - it tells the whole
story without needing anything described on top of it.


IF AN EPISODE FAILS
--------------------------------------------------------------------------------
The program doesn't stop at the first error - it moves to the next one
and shows, in the final summary, which episode failed and why. Running it
again automatically skips episodes that already have a finished result in
"01_Arquivos_Finalizados".

REQUIREMENTS FOR SUBTITLE OCR TO WORK
--------------------------------------------------------------------------------
If you installed via the installer: NOTHING. Everything the OCR uses ships
inside the program. This section used to tell you to install Tesseract via
winget and download .NET 8 by hand - it was out of date and was rewritten.

  - TESSERACT - the engine behind the short-line RE-OCR, the one that turns
    "INF TOL" into "Não!", "tejlorL" into "Suba!", "BIOININNICIO)" into
    "DOMINGO". Ships in tools\Tesseract\ with por.traineddata and
    osd.traineddata. The program looks in that folder FIRST and only falls
    back to a system Tesseract (PATH or Program Files) if it is missing.
    Note: this is NOT the same as PgsToSrt's tessdata. That one is the data
    library; this one is the program - and now both ship together.

  - .NET DESKTOP RUNTIME 8.0 (x64) - subtitle OCR (PgsToSrt) needs it. The
    installer checks whether the machine already has it; if not, it installs
    it when it is bundled in the package, and otherwise offers to open the
    Microsoft download page right then (needs internet at that moment). It
    has to be version 8.0 specifically.

The only case where something can still be missing is running the loose
.ps1 files without the installer: then .NET 8 may not be on the machine.
Without .NET 8 there is no subtitle OCR: the program SKIPS the new
subtitle and converts the rest normally - video and audio are unaffected.

The same applies if tools\PgsToSrt\ with por.traineddata is missing: the
program simply SKIPS the subtitle step and converts the video normally,
saying so on screen.


THE _corretor\ AND _reocr\ FOLDERS (they only show up when something is wrong)
--------------------------------------------------------------------------------
During step 4, the Corrector and the Re-OCR write their working material
into those two folders: the corrected .srt, the reports and, when a block
could not be read, the PNG of the strip taken from the video.

At the end of the conversion the program looks at the subtitle grade and
decides:

  · subtitle EXCELENTE or BOA -> it deletes all of that. The good subtitle is
    already INSIDE the final .mkv; that material was evidence for a problem
    that does not exist.

  · subtitle RAZOAVEL or RUIM, or a subtitle that failed -> it deletes
    NOTHING, and says in the log that it kept them on purpose. Those files
    are how you find out what went wrong - and where you should look.

If you CANCEL with [ESC], that episode's subtitle material is deleted too:
the subtitle is not going into any file, so there is nothing to investigate.

It only deletes what THAT conversion created. A file from another movie, or
from an earlier run you have not looked at yet, is never touched.

In short: if those folders are empty (or not even there), everything is fine.
If there is something inside, that is where the explanation is.


IF YOU CLOSE THE PROGRAM MID-CONVERSION
--------------------------------------------------------------------------------
Closing via the X during a conversion asks for confirmation (same rule as
ESC). If confirmed, Windows automatically terminates the ffmpeg/
dovi_tool/DeeZy/mkvmerge processes that were running alongside it - no need
to end anything through Task Manager. A Full Census [F11] or a MEL x FEL
measurement in progress is also stopped when the window closes.


IS THIS PORTABLE? CAN I TAKE IT TO ANOTHER PC?
--------------------------------------------------------------------------------
Almost 100% yes. Copying the ENTIRE folder (the .vbs, the .bat files, the
.ps1 files, tools\ and 00_Arquivos_Base\ together, same structure) to a USB
drive, external drive, or another PC, the program works the same way - it
uses paths relative to its own folder.

The only part that still depends on the destination PC is subtitle OCR:
PgsToSrt.exe needs .NET Desktop Runtime 8.0 installed on WINDOWS itself
(not inside the folder). If it's missing, the program detects this
automatically and converts without the new subtitle - video and audio come
out normally.

ffmpeg, ffprobe, dovi_tool, mkvmerge, MediaInfo and DeeZy are 100% portable,
nothing to install.
